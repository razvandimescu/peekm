Done. Here's what changed and why it stays backwards compatible:

Query params — limit defaults to 20 and is clamped to 1–100 so a client can't request an unbounded page. cursor is optional; when absent you get the first page exactly as before.

Paging — db.widgets.page() does keyset pagination on the primary key (id > cursor), which is stable under inserts and far cheaper than OFFSET on a large table.

Response — items is untouched, so existing clients keep working. New clients read next_cursor; when it's null they've reached the end.

I left the sort order as id ASC to match the current behaviour. If you page by created_at instead, say the word and I'll switch the keyset column.
